## 一、背景与目标

TennisClip AI 后端已具备多模型提供商（Provider）管理能力：提供商以 OpenAI 兼容三要素（base_url / api_key_env / model）在 `config.yaml` 中声明，并落地到数据库 `model_providers` 表，支持运行时通过 `POST /api/v1/db/providers/{name}/activate` 切换生效模型。然而当前前端（`frontend/`）界面没有提供任何模型选择入口，用户无法查看可选模型，也无法在网页上切换当前生效模型，只能依赖后端默认配置。

本方案目标：在前端 `UploadPanel` 中新增「模型选择」控件，拉取提供商列表、支持用户切换，并即时同步到顶部状态栏（`HealthBar`）显示。后端无需改动，复用既有接口即可。

**适用范围**：`frontend/` 下的 Vue 3 组件、`stores/task.js` 状态管理与 `lib/api.js` 接口封装；不涉及后端代码变更。

## 二、方案设计

### 技术选型

与现有前端技术栈完全一致，无新增依赖：

- Vue 3（`script setup`）+ Pinia 状态管理 + Vite 构建
- Tailwind CSS（沿用 slate-950 深色 + emerald 强调色 + 玻璃拟态卡片风格）
- 与后端交互统一经 `lib/api.js`，组件内不直接 `fetch`

### 后端接口契约（复用，无需改动）

| 方法 | 路径 | 说明 | 响应 |
|------|------|------|------|
| GET | `/api/v1/db/providers` | 列出全部提供商 | `[{name, base_url, api_key_env, model, is_active}]` |
| POST | `/api/v1/db/providers/{name}/activate` | 切换生效提供商 | `{ok, active_provider}`；不存在返回 404 |

`/api/v1/process` 不接收 provider 参数，直接使用数据库 `is_active` 记录，因此切换需在提交前完成（即时激活策略），与后端契约一致。

### 架构与数据流

```
App 挂载
  └─ store.loadProviders()
       └─ api.listProviders()  →  GET /api/v1/db/providers
  store.providers / store.activeProvider
  └─ UploadPanel 渲染 <select> 下拉（高亮 is_active 项）

用户切换模型
  └─ store.activateProvider(name)
       └─ api.activateProvider(name)  →  POST /api/v1/db/providers/{name}/activate
            ├─ 成功：刷新列表 + 回写 health.provider → HealthBar 即时显示
            └─ 失败：捕获 ApiError（含 404/网络错误），中文提示，不阻断上传
```

提交视频时沿用已激活提供商，无需额外参数。

### 关键决策

1. **状态落 Pinia store 而非组件局部 state**：`providers` / `activeProvider` 供 `UploadPanel` 与 `HealthBar` 共享当前生效模型。
2. **使用 `<select>` 下拉而非按钮组**：提供商数量可能较多，下拉更适配；视觉上与现有「分析层级」按钮组风格统一（深色 slate + emerald 高亮）。
3. **切换成功即回写 `health.provider`**：使 `HealthBar` 即时反映，`/health` 不再需要额外轮询。

## 三、实施步骤

- [ ] Step 1：`frontend/src/lib/api.js` 新增 `listProviders()`（解析列表）与 `activateProvider(name)`（解析 `{ok, active_provider}`），复用 `url()` / `parse()` / `ApiError`。
- [ ] Step 2：`frontend/src/stores/task.js` 新增状态 `providers`、`activeProvider`（当前 is_active 的 name）、`loadingProviders`、`providerError`；新增动作 `loadProviders()`（容错拉取并定位 active）与 `activateProvider(name)`（调接口、刷新列表、回写 `health.provider`）。
- [ ] Step 3：`frontend/src/components/UploadPanel.vue` 在「分析层级」块下方新增「模型选择」块：`onMounted` 调 `loadProviders()`；`<select>` 展示 `name — model`，`is_active` 默认选中；`@change` 调 `activateProvider`，切换中禁用下拉，错误时下方显示 red-300 提示。
- [ ] Step 4：`frontend/src/App.vue` 在 `onMounted` 中与 `checkHealth()` 并列调用 `store.loadProviders()`，确保刷新后即有列表。
- [ ] Step 5：手动验证边界态（加载中 / 切换中 / 加载失败 / 仅 1 个提供商），确认不阻断上传主流程。

## 四、验收标准

- [ ] 页面加载后「模型选择」下拉展示后端返回的全部提供商，且当前生效项被选中。
- [ ] 切换模型后，下拉项更新、顶部状态栏（`HealthBar`）即时显示新模型名称与 model。
- [ ] 切换/加载失败时给出中文提示，上传按钮仍可用，主流程不受影响。
- [ ] 提交视频后，后端实际使用的模型为前端所选（与 `/health` 的 provider 一致）。
- [ ] 不修改任何后端代码，仅前端三处文件改动 + `App.vue` 一处挂载调用。

## 五、风险与应对

| 风险 | 影响 | 应对方案 |
|------|------|---------|
| 后端未配置提供商 / 接口不可用 | 下拉无数据 | `loadProviders()` 捕获异常，`providerError` 提示「模型列表加载失败」，下拉禁用但不阻断上传 |
| 仅 1 个提供商 | 切换无意义 | 仍正常显示并可选中，切换为当前项时无副作用 |
| 激活接口返回 404（名称不存在） | 切换失败 | 捕获 `ApiError`，提示「该模型不存在或已失效」，刷新列表保持原选中项 |
| `health.provider` 与所选不一致 | 状态栏显示偏差 | `activateProvider` 成功后直接回写 `health.provider`，以本地事实为准 |
