## 一、背景与目标

现有高光识别阶段采用「抽帧 → 逐帧图片理解」模式：在 `app/utils/llm.py` 中将视频抽成 base64 图片帧，再以批量 `image_url` 送 LLM。该模式存在两个待优化点：

1. **无法利用视频理解能力**：StepFun 已支持 `video_url` 内容类型，可直接将整段视频送模型自行定位高光，省去抽帧且对时序理解更完整。
2. **管线不可配置**：`app/core.py` 的 `run_pipeline` 四段（预处理/高光识别/剪辑/报告）为硬编码顺序执行，用户无法按需启用/停用阶段，也无法选择高光输入模态或集中调整分析策略。

**目标**：以可插拔策略模式新增「视频理解」媒体输入节点（替换抽帧），把管线改造为可配置（全局启用/停用各阶段、固定顺序），并将分析模式、分析层级、阶段集合沉淀为后端全局配置；同时在前端新增「策略调整」模态框，集中管理阶段开关、分析模式与分析层级（层级选择器从 UploadPanel 迁入）。

**适用范围**：仅影响高光识别阶段的媒体输入策略与管线阶段编排，**保持抽帧路径、报告生成路径零回归**。

### 决策记录（已与用户确认）

| 项 | 决策 |
|----|------|
| 视频 >128MB（StepFun 单文件限制） | **校验告警**：仅 `logger.warning`，不自动切片（720p/30fps、1–5 分钟视频通常远低于 128MB） |
| 节点落地形态 | 可插拔策略模块（新建 `media_strategies.py` + 注册表，`frame`/`video` 双实现） |
| 视频模式是否用 event_detect 候选 | 候选窗口作为**软提示（soft hint）**传入，模型自由定位，同时获得时间锚点 |
| 模态框控制范围 | 控制**管线节点和顺序**（本方案仅启用/停用，顺序固定） |
| 层级选择器位置 | 从 UploadPanel 迁入模态框 |
| 配置作用域 | **后端全局配置**（写 `system_config` KV，类似"模型管理"），影响之后所有任务；**不新增 DB 表 / Alembic 迁移** |

## 二、方案设计

### 2.1 全局配置落点（无新表）

复用既有 `system_config` KV 表 + `config_registry` 注册项 + `config_service` 读写，新增三项配置（category=`pipeline`）：

| key | 类型 | 选项 / 默认 | 说明 |
|-----|------|------------|------|
| `highlight.level` | select | `beginner`/`intermediate`/`professional`/`all`，默认 `intermediate` | 分析层级全局默认 |
| `llm.analysis_mode` | select | `frame`/`video`，默认 `frame` | 高光识别媒体输入策略 |
| `pipeline.stages` | str(JSON) | `["preprocess","highlight","edit","report"]` | 启用的阶段有序列表 |

- `app/config_registry.py` 的 `build_config_items` 新增上述三项。
- `app/services/config_service.py`：
  - `set_config_value` 针对 `pipeline.stages` 增加校验（JSON 解析 + 元素 ∈ `{preprocess,highlight,edit,report}`，非法返回 400）。
  - 新增 `get_pipeline_config(db, config)` → `{enabled_stages, analysis_mode, level}`（DB 覆盖 > 默认值）。
- `app/config.py` 的 `LLMConfig` 增 `analysis_mode: str = "frame"`；`config.yaml` 的 `llm` 段增 `analysis_mode: frame`（静态兜底默认）。

### 2.2 媒体输入策略模块（新建 `app/utils/media_strategies.py`）

与现有 `event_detect` 策略模式（`_STRATEGIES`/`_STRATEGY_ORDER`）一致：

- `MediaInputStrategy`（Protocol）：`name` + `build_media_parts(video_path, candidates, config) -> list[dict]`，仅返回媒体内容块（不含基础 prompt 文本）。
- `FrameStrategy`：迁入现有 `_video_to_image_frames()` + `frame_intro` 文案逻辑，输出 `image_url` 多图块（行为不变）。
- `VideoStrategy`（新建）：
  1. 128MB 校验：`video_path.stat().st_size`，超限 `logger.warning` 后尽力发送、不切片。
  2. `_video_to_video_uri()`：读字节 base64 内联 `data:video/mp4;base64,...`（MIME 用 `video/mp4`，当前预处理统一 mp4）。
  3. 构造单个 `video_url` 块；若 `candidates` 存在则追加"参考候选窗口（仅供参考）"软提示文本。
  4. **视频块排在文本之前**（符合 StepFun 最佳实践）。
- 注册表 `get_strategy(mode)`：`{"frame":..., "video":...}`，未知值回退 `frame`。

### 2.3 LLM 调度改造（`app/utils/llm.py` + `app/services/report.py`）

- `complete_structured` 增参 `analysis_mode: str | None = None`（空取 `config.llm.analysis_mode`）；按策略名决定 prompt 与媒体块先后（video：媒体块在前；frame：prompt 在前）；移除内联抽帧逻辑，改由 `get_strategy` 分发。Mock 分支（`_mock_structured`）保持不变。
- `report.py` 调用 `complete_structured` 时**显式传 `analysis_mode="frame"`**，固定既有抽帧+报告行为，杜绝全局切 video 时误把整段视频送往报告接口。

### 2.4 管线阶段化 + 依赖校验（`app/core.py`）

- `run_pipeline` 增参 `analysis_mode=None`、`enabled_stages=None`（默认全开全序）。
- 固定顺序 `[preprocess, highlight, edit, report]`，逐段 `if stage in enabled:` 包裹；`record_task_start`/`record_task_finish` 始终执行，`record_task_input` 置于 preprocess 块内（preprocess 禁用时后续必禁用，安全）。
- **依赖校验**（非法组合抛清晰错误）：
  - `highlight`/`edit`/`report` 任一启用而 `preprocess` 未启用 → 报错。
  - `edit` 或 `report` 启用而 `highlight` 未启用 → 报错。
- `all` 档跳过报告逻辑保留在原 report 块内。

### 2.5 highlight 视频分支（`app/services/highlight.py` + `app/prompts/highlight_analysis.py`）

- `find_highlights` 增 `analysis_mode` 参数透传 `complete_structured`。
- video 模式后处理改 `_clamp_segments`（仅 `[0, duration]` 合法性）+ `_exclude_prep(highlight, config, [])`（仅按 label/置信度过滤，不强制与候选重叠）；frame 模式逻辑完全不变。
- `build_highlight_prompt` 增 `mode` 参数：video 模式弱化 ±2s 精修、改为"直接观看整段视频独立定位起止秒数"，候选仅作提示；frame 模式文案零改动。

### 2.6 端点集成（`app/main.py` + `app/cli.py`）

- `process_video` 经 `config_service.get_pipeline_config(s, config)` 解析 effective `analysis_mode`/`enabled_stages`；保留 `level` 表单参数（前端传全局值）校验；`_process_one` 增参并透传 `run_pipeline`。
- `cli.py` 传 `analysis_mode=config.llm.analysis_mode`、`enabled_stages` 默认（全开）。

### 2.7 前端策略模态框与状态

- **新建 `src/components/StrategyModal.vue`**：仿 `ProviderManageModal` 范式（`props.open` + `watch` 加载）。含：
  - "管线阶段"四开关（预处理/高光识别/剪辑/报告）；highlight 关闭时禁用 edit/report 并提示依赖。
  - 高光识别下"分析模式"单选（抽帧/视频理解）。
  - "分析层级"四选项（从 UploadPanel 迁入）。
  - 保存分别 `api.configSet('pipeline.stages', JSON.stringify(有序启用列表))` / `api.configSet('llm.analysis_mode', mode)` / `api.configSet('highlight.level', level)`，成功后更新 store 并重新 loadConfig。
- **`UploadPanel.vue`**：删除内联"分析层级"选择器与 `level` ref；新增"策略设置"按钮调 `store.openStrategy()`；submit 改 `emit('submit', file, store.defaultLevel)`。
- **`App.vue`**：header 增加"策略设置"按钮（与"模型管理"并列）；挂载 `<StrategyModal :open="store.strategizing" @close="store.closeStrategy()" />`。
- **`stores/task.js`**：state 增 `strategizing/defaultLevel/analysisMode/pipelineStages`；`loadConfig()` 额外读 `highlight.level`→`defaultLevel`、`llm.analysis_mode`→`analysisMode`、`pipeline.stages`→解析 `pipelineStages`；增 `openStrategy/closeStrategy` 与 `saveStrategy(payload)`。
- **`lib/api.js`**：复用已有 `configSet`/`loadConfig`，无需新增方法。

### 2.8 视觉与交互规范

沿用项目深色玻璃拟态风格（slate-950 底 + emerald-400 主色 + backdrop-blur 半透明面板），与 `ProviderManageModal` 视觉一致：

- 模态框：居中遮罩 + 圆角半透明卡片，`max-w` ≤ 5xl，内容区可滚动（`max-h` + `overflow-y-auto`）。
- 阶段开关：每行左侧阶段名 + 右侧 toggle，切换有颜色过渡；非法依赖下灰显并附提示。
- 分析模式：两个单选卡片（抽帧/视频理解），选中态 emerald 高亮。
- 分析层级：四个按钮（入门/进阶/专业/所有高光回合），选中态 emerald 填充。
- 底部：左侧校验错误文本 + 右侧"取消/保存"，保存中禁用并显示"保存中…"。

## 四、验收标准

1. **抽帧回归**：`llm.analysis_mode=frame`（默认）时，行为与改造前完全一致（媒体块为 image_url 多图、prompt 在前、后处理强锚定候选）。
2. **视频理解**：`llm.analysis_mode=video` 时，highlight 以 `video_url` data URI 整段视频送 LLM（视频块在前），候选作为软提示；返回时间戳仅做 `[0, duration]` 合法性 + 准备段过滤，不再 ±2s 强锚定。
3. **管线阶段化**：通过 `system_config` 停用 `report` 后，任务不再生成报告但高光视频正常；停用 `highlight` 时 `edit`/`report` 被依赖校验拦截并给出清晰错误；顺序固定不可乱序。
4. **配置全局生效**：前端"策略调整"模态框保存后，后续所有任务使用新配置（`config` 端点可查）。
5. **前端交互**：UploadPanel 不再含层级选择器，仅留文件上传 + "策略设置"入口；模态框打开时同步当前配置，保存后刷新 store。
6. **日志规范**：新增日志全部使用 loguru `{}` 占位符，`scripts/check_logging.py` 通过。
7. **测试**：`tests/test_media_strategies.py` 与 `tests/test_pipeline.py` 全绿；零回归用例（frame/report）保持通过。

## 五、风险与应对

| 风险 | 影响 | 应对方案 |
|------|------|---------|
| 视频 base64 使请求体膨胀约 33%，超大视频拖慢接口 | 高耗时/超时 | 仅 128MB 告警不阻断；当前 720p/30fps 1–5 分钟远低于上限；必要时用户可在模态框切回抽帧 |
| 视频模式自由定位导致高光时间戳漂移 | 高光起止不准 | 后处理保留 `_clamp_segments` 时长合法性 + `_exclude_prep` 准备段过滤安全网；候选软提示提供锚点 |
| `pipeline.stages` 误配置成非法组合 | 任务失败 | `config_service.set_config_value` 校验元素集合；`run_pipeline` 依赖校验抛清晰错误 |
| 全局配置影响所有任务，误改难回滚 | 影响范围大 | 复用 `DELETE /api/v1/config/{key}` 恢复默认；模态框默认展示当前生效值 |
| 前端 level 移出 UploadPanel 后提交缺失层级 | 任务层级错误 | UploadPanel submit 改用 `store.defaultLevel`；`loadConfig` 保证启动即载入全局默认 |
