## 一、背景与目标

### 1.1 背景

现有 CV 感知层 6 节点（方案 12 · Step 2）全部是**单实体感知**：

| 节点 | 感知对象 | 输出 |
|------|---------|------|
| `detect.tracknet` | 球轨迹 | track + candidates |
| `detect.court` | 球场 14 关键点 | court |
| `detect.player` | 球员框 + 运动强度 | candidates |
| `detect.pose` | 球员姿态 | pose |
| `post.score_highlights` | 整帧语义（CLIP） | highlight |
| `post.classify_strokes` | 击球动作 | — |

链路中**没有任何"实体间关系"维度**——CLIP 帧级打分只回答"这一帧像不像高光"，分不清"球员在与对手握手"、"球员倒地"、"球员上网压迫"这类**主体间叙事事件**，而这些恰恰是报告叙事和回合价值判断的重要信号。

调研文章（微信公众号「老友视觉笔记」，2026-09）介绍了开源项目 **RelateAnything**（GitHub: Maelic/RelateAnything，论文 arXiv 2609.12552）：

- **53M 参数**（推荐 `relsgg-vits16plus`，DINOv3 ViT-S+/16 主干），A40 单帧 20ms，CPU 单帧 0.8~1.8s，ONNX/wasm 可跑；
- **开放词表谓词**：谓词词表不是分类头，而是推理时现场编码的**文本嵌入库**——换词表不重训（与我们 CLIP `highlight_phrases` 同一设计哲学）；
- **区域输入开放**：框可来自 YOLO/SAM/人工/unnamed，输出标准三元组 `(主语, 谓词, 宾语, 置信度)`；
- **自建 RA-4M 数据集**（47.4 万图、1 万自由文本谓词），跨数据集 mR@50 为基线 2.3~3.5 倍；
- **License 三张皮**：代码 Apache-2.0、DINOv3 主干跟 Meta 许可、内置检测器权重 AGPL。

### 1.2 目标

1. 以**可选工作流节点** `detect.relations` 接入开放词表关系预测，产出关系三元组，补齐感知层的"关系维度"；
2. 两个消费场景（按价值排序）：
   - **报告叙事增强**：关系三元组注入 `report.technical`，报告能写出"球员频繁上网压迫"而非仅帧描述；
   - **高光评分辅助特征**：`celebrating` / `diving` 等关系分并入 `post.score_highlights`，补 CLIP 对叙事性事件的盲区；
3. 完全遵循方案 12 的 CV 契约：`uv sync --extra cv` 依赖组、权重入 `backend/data/models/`、`on_failure="skip"` 级联降级、`CvUnavailable` 统一异常。

### 1.3 非目标

- **不替代** `post.classify_strokes`——网球细粒度动作（正手/反手/发球）靠 pose/DTW，关系模型对此帮助有限；
- **不做逐帧关系推理**——CPU 性能不允许，只做候选窗口内稀疏采样；
- **不改动核心管线** `app/core.py` 与内置预置图的必选链路——节点仅在显式编入图时生效；
- **不引入 AGPL 检测器权重**——检测框走自有 YOLO 路径（见 2.6 合规）。

## 二、方案设计

### 2.1 技术选型

| 方案 | 说明 | 结论 |
|------|------|------|
| **A. RelateAnything（本方案）** | 53M 专用关系模型，开放词表文本嵌入，CPU/ONNX 可跑，Apache-2.0 代码 | ✅ 采用：轻量、与现有零样本哲学一致、可降级 |
| B. 大 VLM 关系理解 | 用 Step 3.7 Flash / 本地 VLM 在 Prompt 中直接问关系 | ❌ 放弃：额外 LLM 调用成本，且帧级问题已由 LLM 高光节点覆盖，关系打分需结构化输出，VLM 幻觉风险高 |
| C. 自训场景图模型 | 标注网球关系数据集自训 SGG | ❌ 放弃：无标注数据、无 GPU 训练条件（对齐方案 12 Step 4 待办） |

选型：`relsgg-vits16plus`（53.2M，官方推荐精度均衡款），优先 ONNX 路径（无 torch 也可推理），与 `--extra cv` 组兼容。

### 2.2 架构位置

```
input.video → preprocess.transcode ─┬─ detect.player ──┐
                                    ├─ detect.court ───┼─→ detect.relations ─→ report.technical（可选入）
                                    ├─ detect.tracknet ┘        │              └→ post.score_highlights（可选入，加权）
                                    └─ candidates ──────────────┘
```

- **上游**：`video` + `candidates`（已有端口，无需新检测链）；节点内部在候选窗口内稀疏抽帧、自跑 YOLO 出框，再送关系模型——**不依赖上游暴露框数据**（`detect.player` 的框已聚合为 candidates，未单独暴露）；
- **下游**：新增端口类型 `relations`，`report.technical` 与 `post.score_highlights` 增加**可选**输入（`optional=True`），未连接时零行为变化；
- 图校验：新增端口不触碰 R1~R10 既有规则（R8 仅约束 `highlight` 入边），`validate()` 对未登记端口类型向后兼容（`PORT_PY_TYPES` 登记后自动纳入类型校验）。

### 2.3 节点契约

```python
# backend/app/workflow/nodes/detect_relations.py
@register(
    NodeSpec(
        type="detect.relations",
        label="关系感知（场景图）",
        category="detect",
        description="开放词表场景图：候选窗口内抽帧→YOLO出框→关系三元组（报告叙事/高光辅助）",
        inputs=[
            Port(name="video", type=PortType.VIDEO),
            Port(name="candidates", type=PortType.CANDIDATES),
        ],
        outputs=[Port(name="relations", type=PortType.RELATIONS)],
        params=[
            ParamSpec(key="vocabulary", ...),      # 逗号分隔网球谓词词表（默认见 2.5）
            ParamSpec(key="frames_per_window", ...),  # 每窗口采样帧数，默认 2
            ParamSpec(key="max_windows", ...),        # 最多处理窗口数，默认 5
            ParamSpec(key="min_score", ...),          # 关系分阈值，默认 0.15
            ParamSpec(key="topk", ...),               # 每帧关系条数，默认 15
        ],
        stage="detecting",
        on_failure="skip",   # 权重/依赖缺失级联降级，对齐 4 个 detect 节点
    )
)
def run(ctx, params) -> dict:  # {"relations": RelationResult(...)}
```

配套契约改动：

1. `spec.py`：`PortType.RELATIONS = "relations"` + `PORT_PY_TYPES` 登记（py 元素类型见下）；
2. `models.py`：新增 `RelationTriple`（subject / predicate / object / score / window）与 `RelationResult`（triples + vocabulary + reasoning）pydantic 模型；
3. 薄封装 `app/utils/cv_relations.py`：复用 `cv_runtime` 运行时与 `CvUnavailable` 异常，`predict_relations(video, windows, vocabulary, ...) -> list[RelationTriple]`，节点内不做业务逻辑；
4. 权重缺失 / onnxruntime 缺失 → 抛 `CvUnavailable` → 节点 skipped → 下游按"来源存活、无产出"继续执行（报告/高光不受影响）。

### 2.4 推理性能预算

CPU 单帧 0.8~1.8s（文章 1 核实测），预算约束来自验收指标（1–5 分钟视频端到端 ≤ 30s 不含 LLM 网络延迟；100 条批量无崩溃）：

| 项 | 默认值 | 估算 |
|----|-------|------|
| 处理窗口数 | 5（`max_windows`） | — |
| 每窗口采样 | 2 帧（`frames_per_window`） | 总 10 帧 |
| YOLO 出框 | 0.14~0.23s/帧 | ≈ 2s |
| 关系推理 | ~1s/帧（CPU 中位） | ≈ 10s |
| 词表现场编码 | 0.7s/次（每任务一次） | ≈ 1s |
| **合计** | — | **≈ 13s ≤ 20s 预算** |

- 节点默认**不编入内置预置图**（`compile_from_legacy` 不产出该节点），仅 CV 预设用户手动编入时才产生耗时——对存量任务零影响；
- 超预算时优先调低 `max_windows`，而非牺牲 `frames_per_window`（单帧关系不确定度过高，文章实测框少时分数低至 0.05）。

### 2.5 默认词表（网球谓词）

`ParamSpec.vocabulary` 默认值（逗号分隔，对齐 CLIP `highlight_phrases` 交互风格）：

```
celebrating, shaking hands, arguing, diving, player down,
rushing the net, watching, pointing, shaking fist, applauding
```

- **高光强信号**：`celebrating`（得分庆祝）、`shaking hands`（赛后握手 = 比赛终点段）、`diving` / `player down`（倒地 = 值得进报告的事件）；
- **报告叙事信号**：`rushing the net`（上网压迫）、`arguing`（争议回合）；
- 用户可整串替换——开放词表换装 10 个谓词实测开销 0.7s，无重训成本。

### 2.6 依赖、权重与 License 合规

| 项 | 方案 |
|----|------|
| 依赖 | 复用 `uv sync --extra cv`（onnxruntime 若缺失则追加进 cv extra 组）；模块级导入零重依赖（对齐 CV 节点契约） |
| 权重 | `backend/data/models/relate_anything/`（gitignore 忽略），fp16 约 105MB；复用/扩展 `backend/scripts/fetch_tracknet_weights.py` 模式新增一键下载脚本 |
| **License** | 代码 Apache-2.0 ✅；DINOv3 主干权重按 Meta 许可逐条确认（**Step 1 前置门禁，不通过则中止本方案**）；**AGPL 的内置检测器权重一律不用**——出框走自有 YOLO 路径，避免与 MIT 协议传染 |

### 2.7 数据落库与持久化

- 关系三元组为结构化数据非文件产物：**不新增 `NodeSpec.persists` 落库 kind**（避免 Alembic 迁移），经 `report.technical` 编入报告 JSON 后随 `report` 产物自然落库；
- `RelationResult` 随 `TaskResult.result_snapshot` 序列化入库，历史查看零改动。

## 四、验收标准

1. **降级契约**：无 `--extra cv` 环境下节点注册与 `/api/v1/workflows/schema` 正常返回；执行时节点 skipped、任务成功、下游报告/高光不受影响；
2. **功能**：含该节点的图执行后产出 `relations` 三元组，报告包含关系叙事段；低分（< `min_score`）三元组被过滤；
3. **性能**：默认参数（5 窗口 × 2 帧）CPU 关系推理 ≤ 20s/任务；不编入图时零额外耗时（存量任务耗时回归 = 0）；
4. **合规**：全链路无 AGPL 权重引入；Step 1 许可确认记录归档；
5. **质量门**：`uv run pytest`（新增用例 ≥ 6：薄封装 mock 3 + 节点 1 + 下游零回归 2）+ `check_logging` 全绿；不触碰既有 295+ 用例。

## 五、风险与应对

| 风险 | 影响 | 应对方案 |
|------|------|---------|
| License 三张皮（DINOv3 Meta 许可 / 检测器 AGPL） | MIT 项目合规风险 | Step 1 设为门禁；只用自托管 ONNX 权重 + 自有 YOLO 出框，逐项确认后归档记录 |
| CPU 慢（0.8~1.8s/帧）冲击 30s 验收线 | 端到端超标 | 窗口稀疏采样（默认 10 帧）+ `max_windows` 可调 + 节点默认不入预置图；GPU 可用时切 torch 路径 |
| 检测框质量决定上限（文章明示） | 关系打分被错误框拖累 | 关系分低分天然压序 + `min_score` 过滤；不硬编故事，宁可少输出 |
| 关系模型对网球细粒度动作区分度有限 | 误判击球类型 | 明确非目标（1.3）：不碰击球分类，只做叙事级关系 |
| 模型对场景信息不足时不确定（实测 0.05 低分） | 输出稀疏、感知"没效果" | 预期内行为：Step 1 用真实网球帧标定词表与阈值，报告侧按"有则增强、无则跳过"设计 |
| 权重 105MB + 推理依赖拉高环境体积 | 部署变重 | 权重 gitignore 不入库、依赖仅 `--extra cv` 可选组、缺权重即 skip |
