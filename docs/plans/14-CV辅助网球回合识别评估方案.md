## 一、背景与目标

### 1.1 背景

[01-需求分析与落地方案](./01-需求分析与落地方案.md) 确立了以 Step 3.7 Flash 多模态模型为核心的全链路（预处理 → 高光识别 → 剪辑 → 报告），其验收指标要求「高光回合识别准确率 ≥ 90%」。当前 highlight 节点依赖 LLM 全帧理解，存在三方面不足：

1. **时序定位粗糙**：LLM 输出的回合起止时间戳误差通常 ±1–2s，直接影响 15 秒集锦切取质量；
2. **训练场景特有干扰**：手机固定机位拍摄的训练视频常有多球同屏（球桶、备用球、地上死球），纯 LLM 易将静止死球误判为有效回合；
3. **成本与稳定性**：长视频抽帧调用多模态模型 token 成本高，且批量 100 条稳定性验收（AGENTS.md 指标）依赖链路低故障率。

**现状前提（v1.1.0 更新）**：[12-本地大模型部署可行性方案](./12-本地大模型部署可行性方案.md) 的 CV 感知层已落地——`detect.tracknet`（TrackNet 球追踪）、`detect.court`（TennisCourtDetector 14 关键点 + 单应矩阵）、`detect.player`（YOLOv8 球员运动分数）、`detect.pose`（MediaPipe 姿态）、`post.score_highlights`（CLIP 零样本评分）、`post.classify_strokes`（cnn/dtw 击球分类）、`post.visualize_track`（多球 tracklet 分段 + 静止球灰标诊断），并预置「CV 增强工作流」（TrackNet 候选 → CLIP 初筛 → 剪辑/报告，LLM 仅出报告）与「CV 增强调试工作流」（叠加轨迹诊断分支）。公开资料（YOLOv8/v10/v11 网球检测 + DeepSORT/ByteTrack 追踪 + 事件状态机）表明，固定机位场景下 CV 前置切片可把回合边界精度提升到帧级，并显著降低 LLM 复核负担。

因此本方案的定位从「自建 YOLO 球检测 + ByteTrack 全管线」调整为：**在既有 CV 节点上补强多球过滤与回合状态机，并以 CLIP 零样本评分替代 LLM 复核**，评估其相对纯 LLM 管线的增益。

### 1.2 目标

本方案回答一个问题：**对 TennisClip 而言，引入「CV 前置切片 + LLM 语义复核」是否最优？如何量化评估？**

具体评估目标：

| 目标 | 说明 |
|------|------|
| G1 网球识别质量 | 单球检测召回/精度，遮挡与暗光下的鲁棒性 |
| G2 多球干扰排除 | 球桶/备用球/死球误入回合状态机的比例 |
| G3 球员识别 | 双人场景 A/B 身份区分与跨回合一致性 |
| G4 回合切分 | 起止时刻精度、击球计数、回合类型（发球/相持/失误）正确率 |
| G5 端到端融合 | CV 切片 + LLM 复核相对纯 LLM 的准确率增益与耗时/成本变化 |
| G6 工程可行性 | 算力（CPU/GPU）、内存、1–5 分钟视频 ≤ 30s（不含推理网络延迟）约束下的可行性 |

### 1.3 适用范围

- 输入：手机固定机位（网侧/看台侧）拍摄的 1–5 分钟训练/对打视频，720p/30fps（现有 preprocess 统一规格）；
- 场景：双人对打为主，允许教练旁观、球桶在画面内；
- 不适配：转播多机位剪辑视频、高速运动无固定机位的比赛录像。

## 二、评估方案设计

### 2.1 候选技术路线（公开调研 + 既有代码现状）

| 路线 | 组成 | 公开参照 | 特点 / 现状 |
|------|------|---------|------|
| R1 纯 LLM 抽帧（现状基线） | Step 3.7 Flash 抽帧 + prompts 约束输出时间戳（`analyze.highlight` + `detect.candidates` ffmpeg 信号） | 现有默认工作流 | 边界 ±1–2s；成本最高；Mock 可回退 |
| R2 事件状态机（CV 主路径） | **既有 `detect.tracknet`（TrackNet 深度球追踪，热图 argmax 单点）+ 既有 `event_detect.track_to_candidates`（`hit_cluster_gap` 回合聚类）** + 本方案补强：`cv_visualize.split_tracklets` 静止段/活球过滤接入候选链 + 击球事件状态机（Δv 突变、落点出界/触网/双误判定）+ `detect.court` 单应矩阵球径约束 | Tennis-Analysis-System（92★）、Tennis-Vision（76★）、[2013 转播回合检测](https://doi.org/10.1080/19346182.2013.819007)、[2025 乒乓球记分牌回合检测](https://doi.org/10.1541/ieejeiss.145.1054) | 球追踪/回合聚类已有，**无需自建 YOLO 球检测器 + ByteTrack**；缺口仅在三处过滤与状态机 |
| R3 视频模型兜底切片 | 微调 Video Swin 分类「有效回合片段」 | [xl-hacker/OnPoint](https://github.com/xl-hacker/OnPoint) | 无逐帧标注时低成本兜底；碎片切片需二次过滤 |
| R4 高光复核（辅） | **既有 `post.score_highlights`（CLIP 零样本评分，已脱离 LLM）** 替代原设想的 LLM 抽帧复核；「CV 增强工作流」已落地该降本链路 | 方案 12 · 5.2 预置图 | G5 对照对象由「LLM vs CV+LLM」修正为「纯 LLM（R1）vs CLIP 零样本（R2+R4）」 |
| R5 球员身份化 | 既有 `detect.player`（YOLOv8 贪心中心匹配，帧间）不足跨回合身份区分；补强为 ReID 外观特征 + 登记制匹配 | [jananikolovska/tennis_player_detection](https://github.com/jananikolovska/tennis_player_detection) | 训练场景主角固定，登记制比通用 ReID 鲁棒 |

**推荐被评估主方案：R2（在既有 TrackNet/court/event_detect 上补强）+ R4（CLIP 零样本，替代 LLM 复核）（+ R5 可选），R1 作为基线，R3 作为降级兜底。**

### 2.2 核心规则定义（评估对象）

多球干扰排除（G2）与回合状态机（G4）的判定规则需先固化，作为评估基准：

1. **静止死球规则**：球轨迹连续 N ≈ 0.5s 速度 < 阈值 → 轨迹丢弃，永不参与回合；
2. **物理球径约束**：经球场透视变换 H 将球框投影到地面，换算「虚拟球径」落在 [10cm, 30cm] 区间才保留（近大远小）；
3. **活球判定**：球轨迹在球场投影内 + 速度突变点邻近球员球拍位置 + 与最近球员挥拍方向一致 → 激活为活球；
4. **回合状态机**：
   - 开始：发球/抛球事件（活球从静止转为抛物线）；
   - 进行中：击球事件 = 球速度 Δv 超阈值且突变点邻球拍区域，记录球员侧交替；
   - 结束：球落点出界 / 触网 / 双误 / 双方静止 ≥ 1.5s。
5. **输出**：`[t_start, t_end, 击球次数, 结束事件类型, 胜者侧]`。

### 2.3 指标体系

| 维度 | 指标 | 定义 | 目标（对齐 AGENTS.md 验收） |
|------|------|------|---------------------------|
| G1 网球识别 | AP / Recall@0.5 | 球框与 GT 球框 IoU≥0.5 判对 | AP ≥ 0.80（参照公开集成方案 0.863） |
| G1 网球识别 | 轨迹完整性 MOTA | 球轨迹与 GT 轨迹匹配率 | ≥ 0.85（遮挡中断后恢复率 ≥ 90%） |
| G2 干扰排除 | 死球误入率 | 静止球被状态机当作活球的回合数 / 回合总数 | = 0（硬指标） |
| G2 干扰排除 | 多球选球正确率 | 双球同屏时活球选择正确的回合占比 | ≥ 0.95 |
| G3 球员识别 | 身份混淆率 | 回合内 A/B 身份交换发生次数 / 回合数 | ≤ 0.05 |
| G4 回合切分 | 起止时刻精度 | 切分边界与 GT 误差 ≤ 1s（≤ 0.5s）的回合占比 | ≥ 0.90 / ≥ 0.70 |
| G4 回合切分 | 回合完整召回 | GT 回合被切出的比例（非碎片、非合并） | ≥ 0.90 |
| G4 回合切分 | 击球计数误差 | 平均 |均击球次数差| | ≤ 1 拍 |
| G5 融合增益 | 高光准确率提升 | R2+R4（CLIP 零样本评分）vs R1（纯 LLM）的回合级准确率差 | +5pp 以上，且总准确率 ≥ 0.90 |
| G5 融合增益 | LLM 调用成本下降 | R2+R4 链路（LLM 仅出报告）vs R1 链路（LLM 出高光+报告）的 token 差 | ≥ 50%（v1.1.0：复核由 CLIP 承担，token 下降来自「LLM 不出高光」而非抽帧数） |
| G6 工程 | 端到端耗时 | 1–5 分钟视频 CV 预处理（不含 LLM 网络延迟） | ≤ 30s |
| G6 工程 | 峰值内存 | CV 管线峰值 | CPU 模式 ≤ 4GB |

### 2.4 可视化人工验证（借助「CV 增强调试工作流」）

G1 网球识别与 G2 多球干扰排除的指标（AP/MOTA/死球误入率）需人工核对检出是否真实，纯数值报告无法区分「球被检出」与「备用球/死球被误判为活球」。现有「CV 增强调试工作流」（`_cv_debug_graph_dict`，`seed_cv_debug_workflow` 幂等种子）已落地该诊断链路：

```
input.video → preprocess.transcode
              → detect.tracknet ──(track)──→ post.visualize_track → track_overlay.mp4
              → post.score_highlights → edit.concat / report.technical → output.artifact
```

`post.visualize_track` 产物 `track_overlay.mp4`（经 `persists` 落库，`GET /api/v1/tasks/{id}/artifact/track_overlay` 下载）包含：

| 叠加层 | 语义 | 人工核对用途 |
|---|---|---|
| 球轨迹折线（按 tracklet 分段配色：青/品红/黄/蓝轮换） | 不同段 = 不同球（时间间隔 > `break_gap` 或隐含速度 > `max_speed` 断线） | G1/G2：多球同屏时不同球是否被分段区分 |
| 静止段灰标（`is_static_segment`：点落首点半径内且时间跨度 ≥ `min_span`） | 地上的备用球/捡球 | G2 死球误入率：静止段不应进入候选 |
| 当前帧最近检出点（绿=置信度达标 / 橙=低置信 / 红=未检出） | 该帧是否有球 | G1 召回：漏检帧定位 |
| 球员检测框（YOLOv8，每 `player_stride` 帧） | 球员位置 | G3 球员识别辅助 |
| HUD 统计（轨迹点数 / 检出覆盖率 / tracklet 段数） | 全局检出健康度 | G1 MOTA 粗判 |
| 底部检出时间线（绿=有检出 / 红=无检出 / 白线=播放头） | 时间维度覆盖 | 捡球间隙定位（§2.2 规则 4 静止 ≥1.5s 结束规则的人工验证） |

**人工验证流程（G1/G2 指标的金标核对）**：

1. **激活诊断预设**：`POST /api/v1/workflows/{id}/activate` 激活「CV 增强调试工作流」（或前端「工作流」面板选中）；CV 依赖组 `uv sync --extra cv` + TrackNet 权重就位（`backend/scripts/fetch_tracknet_weights.py` 一键获取）。
2. **提交任务**：`POST /api/v1/process` 上传 1–5 分钟训练视频（含多球子集），任务在 `detect.tracknet` 节点逐帧推理，`post.visualize_track` 产出 `track_overlay.mp4`。
3. **人工逐回合核对**（对照 D3 金标集 §2.5 的 `start_frame, end_frame, strike_frames[], end_type`）：
   - 播放 `track_overlay.mp4`，用播放头白线对齐金标回合边界；
   - **G1**：金标回合内球轨迹是否连续（红色未检出帧数 = 漏检）；
   - **G2**：静止段（灰标 `static?`）是否落在金标的「回合外」（球桶/捡球区），若静止段与某回合重叠 → 死球误入，记录为该回合 G2 Fail；
   - **多球选球**：双球同屏时，被后续回合引用的轨迹段是否对应「活球」金标轨迹（非备用球）；
   - **捡球间隙**：时间线红色段是否覆盖金标的回合间静止区间（验证 §2.2 规则 4「双方静止 ≥1.5s 结束」）。
4. **调参验证**：若多球跳变明显（`cv_visualize` 注释已明示 TrackNet argmax 单点帧间跳变），调大 `max_speed` 节点参数重新渲染（镜头特写球场占画面比例大时），或调小 `break_gap`；重跑核对直至 G2 死球误入率清零。
5. **记录**：每条视频的人工核对结果（G1 漏检帧数 / G2 静止段误入次数 / 多球选球正确）写入评估报告，与 `backend/evals/` 自动指标（AP/MOTA/选球正确率）交叉验证——**人工核对为金标，自动指标为初筛**。

> 该链路零代码即可用于 G1/G2 验收：`post.visualize_track` 为 `on_failure="skip"` 终端诊断节点，缺 CV 依赖/权重时仅诊断分支跳过，主链路集锦/报告产物不受影响（§2.2 规则 1/2/3 的过滤逻辑接入 `track_to_candidates` 后，`track_overlay.mp4` 同步反映过滤效果——静止段被丢弃后时间线红色段增多，可供回归验证过滤未误杀活球）。

### 2.5 评测数据集（自建 + 公开）

| 数据 | 来源 | 用途 | 规模建议 |
|------|------|------|---------|
| D1 训练视频集 | 自有手机固定机位素材（含多球、暗光、遮挡子集） | 真实分布评测 | ≥ 30 条 / 每子集 ≥ 10 条 |
| D2 球检测标注 | Roboflow 开源网球数据集 + 自有补标（参照 [UTennis](https://github.com/YouruiGuo/UTennis) 事件标注范式） | 训练/微调 YOLOv8s（player/ball/strike 三分类） | 检测 ≥ 3k 张，标注回合级 GT ≥ 300 个 |
| D3 回合 GT 金标集 | 人工逐回合标注起止帧 + 击球计数 + 结束类型（参照 [OpenTTGames 扩展版](https://arxiv.org/abs/2512.19327) 逐帧球坐标 + bounce/net 事件范式） | G4/G5 金标评测 | ≥ 100 回合，覆盖发球/相持/失误/双误 |
| D4 公开基准（可选） | Tennis-Analysis-System 等仓库所用素材 | 交叉验证 | 少量 |

标注规范：回合 GT 使用 720p/30fps 帧号标注（与 preprocess 规格一致），每个回合记录 `start_frame, end_frame, strike_frames[], end_type, winner_side`。

### 2.6 对比评估矩阵

| 实验 | 配置 | 评估指标 | 人工验证（§2.4 可视化） | 结论判据 |
|------|------|---------|--------------------------|---------|
| E1 基线 | R1 纯 LLM（现有默认工作流） | G4、G5、G6 | 不适用（纯 LLM 无 track 产物） | 产出基线数值 |
| E2 CV 主路径 | R2（TrackNet + `split_tracklets` 过滤 + 状态机） | G1–G4、G6 | 「CV 增强调试工作流」跑 `post.visualize_track`，人工核对 G1 漏检帧 / G2 静止段误入 / 多球选球（§2.4 流程 1–5） | G2 死球误入率 = 0 且 G4 完整召回 ≥ 0.90 才通过 |
| E3 融合 | R2 + R4（`post.score_highlights` CLIP 零样本复核） | G5、G6 | 同 E2，另核对 CLIP 选中的高光段与人工判定一致 | G5 准确率增益 ≥ +5pp 且 LLM 调用成本 ↓ ≥ 50% 才值得上线 |
| E4 兜底 | R3 替代 R2（视频模型切片） | G4、G6 | 不适用（无 track 产物） | 仅当 E2 训练数据不足时的降级评估 |
| E5 身份化 | E3 + R5（ReID 登记制） | G3 | 球员框叠加（YOLOv8）辅助核对 A/B 身份 | 身份混淆率 ≤ 0.05 |

Mock 模式约束：E3/E4/E5 在 LLM Mock 模式下自动退化为纯 CV 结果（与现有 `llm.mock_mode: auto` 契约一致），评估报告需同时记录「真实模型」与「Mock」两组数据。

### 2.7 工程实现落点（与 AGENTS.md 契约对齐，v1.1.0 重写）

不再新建 `services/cv_slice.py`（方案 12 已落地 CV 感知层），改为在既有模块上补强三处：

1. **多球过滤接入候选链**（G2 核心）：`event_detect.track_to_candidates` 当前把 TrackNet 逐帧点按 `hit_cluster_gap` 直接聚为候选，静止球/备用球会混入。复用 `cv_visualize.split_tracklets`（时间间隔 + 隐含速度断线，静止段判定）对轨迹先分段，丢弃静止段与低于 `min_ball_diameter`（经 `detect.court` 单应矩阵换算）的段，再聚候选；
2. **击球事件状态机**（G4 核心）：在 `event_detect` 内新增 `track_to_rallies`（或独立 `rally_state_machine` 函数），按 §2.2 规则 4/5 输出 `[t_start, t_end, 击球次数, 结束事件类型, 胜者侧]`；阈值走 `HighlightConfig` 可配项（静止 1.5s、Δv 阈值、球径区间），评测集覆盖 ≥ 2 种场地；
3. **节点接入**：`detect.tracknet` 增加 `ball_filter` 参数（off/tracklet）控制是否启用过滤；新增可选节点 `post.rally_state`（on_failure=skip）消费过滤后轨迹产出回合结构化结果，`report.technical` / `post.score_highlights` 可选入边消费；`models.py` 增加 `RallySlice` / `BallEvent` 结构化结果；
4. **评估脚本** `backend/evals/`（不进 pytest 单测，独立 CLI），输出 JSON 指标报告落 `backend/outputs/`；各节点结果按全链路契约同步落库（`app/core.py` 约定）。

## 四、验收标准

1. 评估报告覆盖 E1–E5 全部实验，含 G1–G6 全指标数值与 Pass/Fail 判定；
2. G2 死球误入率 = 0（多球干扰排除为训练场景硬需求，未达成则 E2/E3 判 Fail）——**人工核对手段**：「CV 增强调试工作流」`post.visualize_track` 产物 `track_overlay.mp4`，静止段（灰标 `static?`）不落入任何金标回合（§2.4 流程 3）；
3. G4 回合切分：完整召回 ≥ 0.90，起止误差 ≤ 1s 的回合占比 ≥ 0.90；
4. G5 融合：准确率 ≥ 0.90（对齐 01 方案验收指标），R2+R4 链路 LLM 调用成本较 R1 下降 ≥ 50%（v1.1.0：复核由 CLIP 零样本承担，成本下降来自 LLM 不出高光而非抽帧数）；
5. G6 工程：1–5 分钟视频 CV 前置处理 ≤ 30s（不含 LLM 推理网络延迟），CPU 峰值内存 ≤ 4GB；
6. Mock 模式下 E3 可自动降级为纯 CV 结果且不崩溃（对齐 AGENTS.md「连续 100 条批量无崩溃」）；
7. **可视化诊断可用**：「CV 增强调试工作流」激活后 `post.visualize_track` 节点可渲染 `track_overlay.mp4`（tracklet 分段 / 静止灰标 / 时间线齐备），缺 CV 依赖/权重时诊断分支按 `on_failure=skip` 级联跳过、主链路集锦/报告产物不受影响。

## 五、风险与应对

| 风险 | 影响 | 应对方案 |
|------|------|---------|
| 自有训练素材不足，多球/暗光子集 < 10 条 | G2 评估不置信 | 先按 D2 公开数据 + 合成遮挡增强训练；补采素材前 E2 结论标注「低置信」 |
| 720p 小目标球检测 AP 不达 0.80 | G1 拖垮 G4 | 上 SAHI 切片推理 + YOLOv8s/v10n 加权框融合（公开参照 0.863 方案） |
| 手机镜头畸变使透视 H 失效 | 球径约束误杀真球 | 标定阶段加径向畸变补偿（`cv2.undistort`），畸变参数随视频缓存 |
| 状态机阈值（静止 1.5s / Δv 阈值）过拟合单一场地 | 跨场地泛化差 | 阈值做成 config.yaml 可配项，评测集覆盖 ≥ 2 种场地（硬地/红土） |
| LLM 复核 token 未达 50% 下降 | G5 经济性不成立 | 抽帧密度自适应：长回合降采样、事件帧必采 |
| Mock 模式评估与真实模型偏差大 | 决策误导 | Mock 仅验证稳定性，G5 增益判定以真实 Step 3.7 Flash 结果为准 |
| **（v1.1.0 新增）TrackNet 单点 argmax 在多球同屏时帧间跳变**（`cv_visualize` 注释已明示） | G2 死球误入率难达 =0，跳变点被 `track_to_candidates` 聚成虚假候选 | `split_tracklets` 静止/速度断线分段 + §2.2 规则 3 活球判定必须在候选链生效；`post.visualize_track` 诊断分支用于跳变定位 |
| **（v1.1.0 新增）`CV 增强工作流` 把 CLIP 评分当高光、无 LLM 复核** | G5 的「LLM token 下降 ≥ 50%」失去原对照对象（纯 LLM 高光 vs CV+LLM 复核） | G5 改定义为「纯 LLM（R1）vs CLIP 零样本（R2+R4）」的准确率/成本对照，token 指标降级为可选观测项 |
| **（v1.1.0 新增）既有 `hit_cluster_gap_seconds=4s` 把捡球间隙聚进候选** | G4 回合完整召回被稀释（长间隙跨回合合并） | 状态机「双方静止 ≥ 1.5s 结束」规则（§2.2 规则 4）在 `track_to_candidates` 之后做二次精修切分，而非仅靠间隔聚类 |
