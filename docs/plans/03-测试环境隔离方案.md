## 一、背景与目标

当前后端配置体系已支持「环境变量 > `.env` > `config.yaml` > 代码默认值」的优先级链，并存在 `TENNISCLIP_DATA_DIR` 覆盖机制（`backend/app/config.py`）。但测试代码与开发代码共享同一份 `backend/.env` 与同一数据目录 `backend/data/`，存在以下风险：

- 测试过程中若未显式切换，可能向真实的 `data/` 写入数据库、输入输出与日志，污染开发数据；
- `.env` 中的敏感凭据/连接串在测试环境未必适用，缺乏独立收敛点；
- 仓库根遗留 `backend/test_roundtrip.db` 等测试文件，目录散落。

**目标**：引入 `.env.test` 作为测试专属配置，并以 `TENNISCLIP_ENV=test` 自动切换；测试数据（数据库、输入/输出、日志）统一落入 `backend/data_test/`，开发/生产数据零污染。仅提交 `.env.test.example` 脱敏模板，`.env.test` 不入库。

**适用范围**：`backend/` 全部测试（`pytest`）、配置加载层、Alembic 迁移、CI 配置。

## 二、方案设计

### 2.1 配置加载层扩展

改造 `backend/app/config.py` 的 `load_config()`：

```python
def load_config(
    config_file: Optional[str | Path] = None,
    env_file: Optional[str] = None,
) -> AppConfig:
    """加载配置：环境变量 > .env(.env.<env>) > config.yaml > 代码默认值。

    env_file 缺省时，按 TENNISCLIP_ENV 选择，遵循 .env.<env> 约定：
      - TENNISCLIP_ENV=test → .env.test
      - TENNISCLIP_ENV=prod → .env.prod
      - 缺省 / 其他          → .env
    config_file 可显式指定 config.yaml 路径（缺省读仓库根 config.yaml）。
    """
    if env_file is None:
        env_name = os.environ.get("TENNISCLIP_ENV")
        env_file = f".env.{env_name}" if env_name else ".env"
    load_dotenv(_PROJECT_ROOT / env_file, override=False)
    ...
```

- `load_config` 为公共加载器，**不感知任何具体环境（含 test）**：仅按 `.env.<env>` 约定选文件，并通过既有的 `TENNISCLIP_DATA_DIR` 覆盖链装配 `paths.data_dir`。
- 复用既有 `TENNISCLIP_DATA_DIR` 覆盖链：`.env.test` 中设置 `TENNISCLIP_DATA_DIR=data_test`，测试数据自然落入 `backend/data_test/`。
- 测试数据目录的**兜底（未声明时默认 `data_test`）已移至 `conftest.py` 初始化阶段**，不再在 `load_config` 内硬编码。
- 保留 `load_dotenv(override=False)`：进程注入（CI/K8s）的环境变量始终优先于 `.env.test`，安全边界不退化。
- 向后兼容：未设置 `TENNISCLIP_ENV` 时行为与现状完全一致（加载 `.env`）。

### 2.2 新增 `ensure_data_dir()`

在 `AppConfig` 上新增方法，保证统一数据目录存在（SQLAlchemy 连接 SQLite 前父目录必须存在）：

```python
def ensure_data_dir(self) -> Path:
    """确保统一数据目录（data_test / data）存在，供数据库/输出前置创建。"""
    data = self.data_path
    data.mkdir(parents=True, exist_ok=True)
    return data
```

### 2.3 测试环境注入（conftest）

新增 `backend/tests/conftest.py`，pytest 启动时：

```python
import os

# pytest 初始化即确立测试环境：隔离逻辑只存在于测试作用域，不污染公共代码。
# 1) 标记环境，使 load_config() 按 .env.<env> 约定加载 .env.test
os.environ.setdefault("TENNISCLIP_ENV", "test")
# 2) 兜底：即使 .env.test 缺失或未声明数据目录，也统一落入 data_test，
#    绝不误写真实 data/。.env.test 中显式声明的 TENNISCLIP_DATA_DIR 可正常覆盖。
os.environ.setdefault("TENNISCLIP_DATA_DIR", "data_test")
```

并提供一个会话级 fixture 调用 `load_config().ensure_data_dir()` 预建 `data_test/` 目录。既有测试代码中所有 `load_config()` 调用无需改造即获得隔离。

### 2.4 测试 DB 对齐

`test_pipeline.py` 的 `test_db_service_roundtrip` 原自建 `backend/test_roundtrip.db`（仓库根遗留，已被 `.gitignore` 忽略）。改为使用配置驱动的 `data_test` 目录（`load_config().data_path / "test_roundtrip.db"`），彻底隔离并复用既有 `.gitignore` 规则，避免仓库根散落测试文件。

### 2.5 模型提供商种子纳入隔离

`model_providers` 表在服务启动建表后由 `init_db` 种子写入（表为空时），来源为当前生效配置。该写入同样受本方案隔离约束，不会污染开发数据：

- `app/services/db_service.py` 的 `init_db(config)` 调用 `db_models._seed_providers(config)`，**直接复用调用方已持有的 config**；在测试作用域下该 config 由 `conftest` 的 `TENNISCLIP_ENV=test` 驱动，等价于 `.env.test`，故种子写入测试库（`data_test/` 下的 SQLite）。
- `app/db.py` 的 `init_db(engine)`（Alembic 路径）无 config 参数，就地 `load_config()` 后再传给 `_seed_providers`；因 conftest 已写死 `TENNISCLIP_ENV=test`，此处 `load_config()` 同样加载 `.env.test`，与运行时同源。

> **反模式提醒**：切勿在 `_seed_providers` 内重新 `load_config()` 或从磁盘 `config.yaml` 读 `active_provider` 判定，否则在测试环境会绕开 `.env.test` 隔离、把开发期 `active_provider` 写进测试库。当前实现已由 `init_db` 统一传入 config，种子与生效提供商判定始终基于同一份（测试）配置。

## 四、验收标准

- 运行 `uv run pytest` 时，所有 `load_config()` 加载 `.env.test`，且 `config.data_path` 解析为 `backend/data_test/`，期间 `backend/data/` 不被创建或写入；
- `backend/.env.test` 被 `.gitignore` 忽略，`git status` 不可见；`.env.test.example` 正常入库；
- `data_test/` 被 `.gitignore` 忽略，测试产物不入库；
- 未设置 `TENNISCLIP_ENV` 时（如 `uv run uvicorn app.main:app`），仍加载 `.env` 且数据落在 `data/`，行为与改造前一致；
- `uv run pytest` 全部用例通过；`backend/.env.test` 不设置 `TENNISCLIP_LOG_LEVEL`，不干扰 `test_logging.py` 级别断言。

## 五、风险与应对

| 风险 | 影响 | 应对方案 |
|------|------|---------|
| 开发者未创建 `.env.test` 即跑测试 | `data_test` 未指定，回落到默认 `data/` | conftest 初始化即 `setdefault("TENNISCLIP_DATA_DIR", "data_test")` 兜底，且 `TENNISCLIP_ENV=test` 已写死；无需 `load_config` 内硬编码兜底 |
| `.env.test` 误提交含真实凭据 | 凭据泄露 | `.gitignore` 严格忽略 `backend/.env.test`，仅提交脱敏的 `.env.test.example` |
| `test_db_service_roundtrip` 迁移路径后残留旧库 | 仓库根遗留文件 | 清理既有 `backend/test_roundtrip.db`，统一落 `data_test/` |
| Alembic 迁移在测试环境指向异常 | 迁移库错乱 | Alembic 读取 `DATABASE_URL`/`load_config()` 与运行时同源，`.env.test` 设置 `DATABASE_URL=sqlite:///./data_test/tennisclip_test.db` 即一致 |
| `test_logging.py` 受其他测试导入的第三方（uvicorn 等）污染 | 标准库 logging 被静默禁用（`logger.disabled=True`/`logging.disable`），TC-04 拦截断言落空 | 日志测试自管隔离：`_reset_logging` 夹具在每个用例前后重置标准库全局状态（复位 `logging.disable(0)`、被接管 logger 的 `level/handlers/propagate/disabled`、清理残留 `InterceptHandler`），不依赖本方案的数据目录隔离 |
