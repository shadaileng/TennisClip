## 一、背景与目标

### 1.1 现状

当前处理链路是**固定顺序的策略管线**：`core.run_pipeline` 内部硬编码四个阶段，`pipeline.stages` 配置只能做「开关」，顺序不可变。

```python
# backend/app/core.py
DEFAULT_STAGES: list[str] = ["preprocess", "highlight", "edit", "report"]

def run_pipeline(video_path, config, result, level="intermediate",
                 analysis_mode=None, enabled_stages=None) -> TaskResult:
    ...
    if "preprocess" in enabled: ...      # 1 预处理
    if "highlight"   in enabled: ...     # 2 高光识别
    if "edit"        in enabled: ...     # 3 剪辑合成
    if "report"      in enabled: ...     # 4 技术报告
```

阶段依赖也写死为一组 if 判断：

```python
# backend/app/core.py
def _validate_enabled_stages(enabled: set[str]) -> None:
    if ("highlight" in enabled or "edit" in enabled or "report" in enabled) and "preprocess" not in enabled:
        raise ValueError("管线依赖非法：高光识别/剪辑/报告 依赖 预处理，启用前须先启用预处理阶段")
    if ("edit" in enabled or "report" in enabled) and "highlight" not in enabled:
        raise ValueError("管线依赖非法：剪辑/报告 依赖 高光识别，启用前须先启用高光识别阶段")
```

### 1.2 局限

| # | 局限 | 具体表现 |
|:--:|------|---------|
| 1 | 顺序不可变 | `DEFAULT_STAGES` 固定为 `preprocess → highlight → edit → report`，只能取子集启停，无法调整顺序 |
| 2 | 节点不可插入/不可复用 | 无法插入「段过滤」「均匀切片兜底」「水印/BGM/字幕」；无法同一节点使用两次（如双路高光取并集） |
| 3 | 参数不随节点走 | 参数全部来自全局 `AppConfig`（`config.yaml`），不能给单个节点独立配置 `level` / `target_duration` / `candidate_mode` |
| 4 | 无分支与聚合 | 无法表达「视频理解 + 信号候选」双路并行后合并 |
| 5 | 扩展成本高 | 每加一个节点都要改 `DEFAULT_STAGES`、`_validate_enabled_stages`、`core.run_pipeline` 三处 |
| 6 | 前端强耦合 | `frontend/src/components/TaskCard.vue` 把四个 stage key 写死成步骤条，自定义链路后进度展示失真 |

### 1.3 目标与非目标

**目标**

- 视频处理过程抽象为「**节点 + 类型化端口 + 有向无环图**」，用户可增删、排序、启停节点并配置节点参数。
- 工作流可**命名保存为多套预设**、可**激活**一套作为默认、可**导入/导出 JSON**。
- 新增处理节点只需注册，**不修改执行器与前端**（前端表单由参数 Schema 驱动）。
- 默认工作流与现有四段管线行为**逐字段等价**，既有测试、CLI、前端结果展示零回归。

**非目标（本期不做）**

- 节点级缓存与「从选中节点重跑」（成本高，列为后续迭代）。
- 图内并行执行（保持拓扑串行，可复现、易排错）。
- 子图 / 节点分组 / 循环结构。

### 1.4 决策结论（已确认）

| 决策点 | 结论 |
|--------|------|
| 前端交互形态 | **SVG 画布编辑器**（`WorkflowCanvas.vue`）：纯 SVG + 鼠标事件，零外部依赖，支持节点拖拽、端口连线、滚轮缩放、空白平移 |
| 旧策略面板兼容 | **保留** `pipeline.stages` / `llm.highlight_strategy` / `llm.analysis_level` 作为「简易模式」，运行时编译成默认图，老用户零感知 |
| 交付范围 | **一次性端到端**：后端内核 + 持久化/API + 前端画布编辑器 |
| 持久化方式 | **新增 `workflows` 表**（支持多套预设、命名、导入导出、激活），走 Alembic 迁移 |

**一句话概括**：图是唯一真相源；简易模式只是「编译成图」的一种输入；执行器只认图。

### 2.2 数据契约：端口类型

| 端口类型 | 载荷 | 产出节点 | 消费节点 |
|---|---|---|---|
| `video` | `pathlib.Path`（源文件 / 预处理文件 / 集锦文件） | `input.video`、`preprocess.transcode`、`edit.concat` | 抽帧、剪辑、报告、产物输出 |
| `duration` | `float`（秒） | `preprocess.transcode` | 候选定位、均匀切片 |
| `candidates` | `list[Segment]` | `detect.candidates` | LLM 高光精修 |
| `highlight` | `HighlightResult` | `analyze.highlight`、`post.*`、`edit.concat`(透传) | 剪辑、报告、产物输出 |
| `report` | `TechnicalReport` | `report.technical` | 产物输出 |

端口类型即**连线合法性的唯一判据**：`from_port.type != to_port.type` 的连线在图校验阶段直接拒绝。

### 2.3 节点目录（首期 9 个）

| type | 类别 | 输入 | 输出 | 关键参数 | 说明 |
|---|---|---|---|---|---|
| `input.video` | 输入 | — | `video` | — | 由执行器注入任务源视频 |
| `preprocess.transcode` | 预处理 | `video` | `video`, `duration` | `height`(720)、`fps`(30)、`max_input_seconds`(300) | 封装 `preprocess.preprocess` + `probe_video`；同时落 `record_task_input` |
| `detect.candidates` | 信号 | `video`, `duration` | `candidates` | `mode`(`audio_motion`)、`top_n`(5) | 封装 `event_detect.detect_candidates`；`top_n=None` 表示放开上限 |
| `analyze.highlight` | LLM | `video`, `duration`, `candidates`* | `highlight` | `level`、`analysis_mode`、`model`* | 封装 `highlight.find_highlights`；`expensive=True`；`model` 为空时使用默认配置 |
| `post.filter_segments` | 后处理 | `highlight` | `highlight` | `min_confidence`(0.6)、`exclude_labels`、`min_duration` | 抽自 `segment_ops.py`；过滤低置信度与黑名单标签段 |
| `post.uniform_slices` | 后处理 | `duration` | `highlight` | `count`、`slice_seconds` | 抽自 `segment_ops.py`，兜底用均匀切片 |
| `edit.concat` | 剪辑 | `video`, `highlight` | `video`, `highlight` | `target_duration`(15)、`all_mode`(false) | 封装 `video_editor.edit_highlight_video`；**透传 highlight** 供下游消费 |
| `report.technical` | 报告 | `video`, `highlight` | `report` | `level` | 封装 `report.generate_report`；`optional=True`（失败不致命，保留集锦） |
| `output.artifact` | 输出 | `video`*, `report`*, `highlight`* | — | — | 产物投影回 `TaskResult`；`highlight` 端口可选（兜底投影机制） |

> `*` 表示**可选输入/参数**：未连线时该端口传 `None`，节点内部沿用既有兜底逻辑。

后续可无痛扩展的节点（仅需新增注册，不动执行器）：`post.merge_highlights`（双路合并）、`edit.watermark`、`edit.bgm`、`edit.subtitle`、`export.multi_resolution`、`export.slow_motion`、`export.pdf`。

### 2.4 参数 Schema（驱动前端表单）

```python
@dataclass(frozen=True)
class ParamSpec:
    key: str                      # 参数名
    label: str                    # 表单标签
    type: str                     # str | int | float | bool | select
    default: Any
    options: list | None = None   # select 类型选项
    min: float | None = None      # int/float 下界
    max: float | None = None      # int/float 上界
    description: str = ""
```

`NodeSpec` 聚合：`type` / `label` / `category` / `description` / `inputs` / `outputs` / `params` / `stage` / `optional` / `expensive`。

前端渲染规则：`bool`→开关、`select`→下拉、`int|float`→数字输入（带 min/max）、`str`→文本框。新增参数仅需后端加一行 `ParamSpec`。

`analyze.highlight` 的 `model` 参数由 `build_schema()` 动态填充：从 `ai_providers` DB 表读取所有启用模型，格式为 `服务商名/model_id`；空字符串表示使用默认配置。

### 2.6 图校验规则（R1~R10）

| 规则 | 判定 | 错误文案（示例） |
|---|---|---|
| R1 节点类型已注册 | `type ∈ registry` | `未知节点类型：xxx` |
| R2 节点 id 唯一 | 无重复 id | `节点 id 重复：n2` |
| R3 端口存在 | `from/to` 的端口在 NodeSpec 中定义 | `节点 n2 不存在输出端口 xxx` |
| R4 端口类型匹配 | 两端 `PortType` 相同 | `连线类型不匹配：video → duration` |
| R5 必填输入已连线 | 每个非可选输入端口至少一条入边 | `节点 n4 的必填输入 video 未连接` |
| R6 单输入端口唯一 | 非多入端口仅允许一条入边 | `节点 n5 的输入端口 highlight 存在多条连线` |
| R7 无环 | Kahn 拓扑排序能消费全部节点 | `工作流存在环：n2 → n3 → n2` |
| R8 存在输出节点 | 至少有一个 enabled 的 `output.artifact` | `工作流缺少 output.artifact 输出节点` |
| R9 孤立节点 | enabled 节点至少一条入边或出边 | `孤立节点：n3` |
| R10 参数合法 | 按 `ParamSpec` 校验类型/范围/选项 | `参数 level 取值非法：xxx` |

`validate()` **不抛异常**，返回结构化结果 `{ok: bool, errors: [{node, code, message}]}`，便于前端在画布中逐节点标红。

### 2.7 执行器与产物投影

```python
# backend/app/workflow/executor.py
class Executor:
    def __init__(self, graph, config, result, level="intermediate"):
        self.graph = graph
        self.config = config
        self.result = result
        self.level = level

    def execute(self, video_path) -> TaskResult:
        ctx = Context(video_path=video_path, config=self.config, ...)
        db_service.record_task_start(task_id, str(video_path), ctx.level)
        for node_id in self.graph.topo_order():
            node = self.graph.nodes[node_id]
            if not node.enabled: continue
            spec = get_spec(node.type)
            fn = get_fn(node.type)
            ctx.inputs = ctx.resolve_inputs(self.graph, node_id)
            params = resolve_params(spec.params, node.params)
            self.result.stage = spec.stage
            outputs = fn(ctx, params)
            ctx.store(node_id, outputs)
        # 兜底投影：若 result.highlight 仍为空，从上下文输出中查找
        if self.result.highlight is None:
            for _nid, _outs in ctx._outputs.items():
                hl = _outs.get("highlight")
                if hl is not None:
                    self.result.highlight = hl
                    break
        self.result.status = TaskStatus.SUCCEEDED
        db_service.record_task_finish(...)
        return self.result
```

**产物投影**（保证前端零改动的关键）：`output.artifact` 节点把接收到的值按端口名写回 `TaskResult` 既有字段——

| artifact 入端口 | 写回字段 |
|---|---|
| `video` | `result.highlight_video_path` |
| `report` | `result.report` / `result.report_path` |
| `highlight` | `result.highlight` |

**兜底投影**：若 `output.artifact` 未收到 `highlight` 输入（用户图可能漏连边），执行器从上下文输出中自动查找并注入 `result.highlight`，确保前端 `VideoPlayer` 能正常显示 segments。

**执行顺序确定性**：Kahn 拓扑排序，同一层级按 `node.id` 升序出队，保证同一张图多次执行顺序完全一致（可复现，便于测试与排障）。

### 2.8 持久化设计

**新增表 `workflows`**（`backend/app/db_models.py`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Integer PK | 自增主键 |
| `name` | String(64) unique | 预设名称（唯一） |
| `description` | String(255) | 描述 |
| `graph_json` | Text | 图定义全文（JSON） |
| `is_builtin` | Integer default 0 | 1=内置（只读、不可删除/修改） |
| `enabled` | Integer default 1 | 是否启用 |
| `sort_order` | Integer default 0 | 排序权重 |
| `created_at` / `updated_at` | DateTime | 时间戳 |

激活项走**配置 KV 机制**：`workflow.default_graph_id`（与 `ai.provider` 同模式）；`workflow.mode` 控制执行模式（`legacy` / `workflow`）。

迁移按 AGENTS.md 约定执行 Alembic：

```bash
cd backend
uv run alembic revision --autogenerate -m "add workflows"
# 人工审查 alembic/versions/xxxx_add_workflows.py
uv run alembic upgrade head
```

> 说明：AGENTS.md 中「管线策略走配置 KV、不新增表」的约定针对的是**全局开关类策略**；工作流是多实体（多套预设 + 命名 + 导入导出），KV 无法表达列表与命名，故此为该约定的**显式例外**。

**内置种子**：服务启动且 `workflows` 表为空时，按简易模式三 KV 编译生成「默认工作流」（`is_builtin=1`），保证升级后老行为不变。

### 2.9 配置 KV（工作流相关）

| key | 默认值 | 说明 |
|---|---|---|
| `workflow.mode` | `legacy` | 执行模式：`legacy`=旧固定管线；`workflow`=可编排工作流 |
| `workflow.default_graph_id` | `""` | 激活的工作流 ID（空字符串=使用简易模式编译的默认图） |
| `pipeline.stages` | `["preprocess","highlight","edit","report"]` | 简易模式：启用的管线阶段 |
| `llm.highlight_strategy` | `frame` | 简易模式：高光识别媒体输入策略 |
| `llm.analysis_level` | `intermediate` | 简易模式：分析层级 |

**运行时取值优先级**：显式 `workflow_id` > 激活工作流（`workflow.default_graph_id`）> 由三 KV 编译的默认图。

## 四、验收标准

1. **等价性**：同一视频 + 同一 mock 条件下，默认工作流产出与改造前逐字段一致（TC-35）。
2. **兼容性**：不建立任何工作流、仅设置三个 KV 时，系统行为与改造前完全相同（TC-36、TC-37）。
3. **可编排性**：可通过画布编辑器创建并执行自定义工作流——① 跳过报告；② 先过滤再剪辑；③ 均匀切片兜底。
4. **校验完备**：非法图（环 / 类型不匹配 / 悬空必填 / 缺少输出）一律 400 并返回具体中文原因。
5. **前端可用性**：画布编辑器可拖拽节点、连线、配置参数、保存预设、切换激活、导入导出 JSON。
6. **回归**：`cd backend && uv run pytest tests/` 全绿；`uv run python -m app.cli data/sample_videos/*.mp4` 正常出片。
7. **迁移**：`uv run alembic upgrade head` 一次到位，旧库走 `create_all + stamp head` 兜底。
8. **前端构建**：`cd frontend && pnpm build` 成功，无新增 npm 依赖。

## 五、风险与应对

| 风险 | 影响 | 应对方案 |
|---|---|---|
| 默认图与旧行为不等价 | 回归破坏线上行为 | TC-35 等价性测试为合入前置条件；`run_pipeline` 保留旧签名作对照 |
| 自由度过高拼出非法图 | 任务失败、产物缺失 | 十条校验规则（R1~R10）+ 保存前 `validate` + 内置预设收口 + 画布非法标红 |
| LLM 节点成本高，反复调试烧 token | 成本与时长不可控 | 节点标 `expensive` 并在 UI 提示；`analysis_mode` 保持 frame 默认 |
| 画布编辑器 SVG 性能 | 大量节点时卡顿 | 首期节点数有限（<20），SVG 足够；后续可引入 Canvas 渲染 |
| `highlight.py` 私有函数抽取引入行为漂移 | 识别质量下降 | 抽取为 `segment_ops.py` 后由原函数与新节点**共用** |
| Alembic 迁移与旧库兜底冲突 | 升级失败 | 先 autogenerate 再人工审查；保留 `create_all + stamp head` 兜底 |
| 前端画布与后端校验规则不一致 | 前端放行、后端拒绝 | 校验逻辑**只在后端**，前端调用 `/workflows/validate` 复用同一份结果 |

## 六、工作流使用说明

### 6.1 快速上手

1. **打开画布**：点击顶部工具栏「工作流」按钮，进入全屏画布编辑器
2. **新建工作流**：点击左侧「+ 新建空白」，或点击已有预设加载
3. **添加节点**：点击左上角「+ 添加节点」，从弹出的节点目录中选择（按类别分组）
4. **连接节点**：从节点的输出端口（右侧圆点）拖拽到另一节点的输入端口（左侧圆点）
5. **配置参数**：点击节点，在右侧参数面板中修改参数
6. **保存**：点击顶部「💾 保存」，输入工作流名称
7. **激活**：点击顶部「⚡ 激活」，或在左侧预设列表中悬停点击 ⚡ 图标
8. **执行**：之后提交视频任务时，系统自动使用激活的工作流执行

### 6.2 工作流 vs 简易模式

| 特性 | 简易模式（策略设置） | 工作流（画布编辑器） |
|------|------|------|
| 打开方式 | 顶部「策略设置」按钮 | 顶部「工作流」按钮 |
| 可调参数 | 3 个全局开关（阶段/策略/层级） | 每个节点独立参数 + 自由连线 |
| 预设管理 | 无（仅全局 KV） | 多套命名预设，可切换激活 |
| 节点顺序 | 固定（预处理→高光→剪辑→报告） | 自由编排（DAG） |
| 高级功能 | 无 | 节点启停、JSON 导入导出、模型选择 |
| 适用场景 | 快速使用、不想折腾 | 自定义管线、实验不同组合 |

### 6.3 执行优先级

系统按以下优先级决定使用哪个工作流：

```
显式指定 workflow_id > 激活的工作流（workflow.default_graph_id）> 简易模式编译的默认图
```

- **激活工作流**：在画布编辑器中保存并激活后，后续所有任务自动使用该工作流
- **简易模式**：在「策略设置」中修改三个 KV 后，编译为默认图执行（不改变激活状态）
- **无任何配置**：使用内置默认工作流（等价于原始四阶段管线）

### 6.4 节点连接规则

- **端口类型必须匹配**：`video` 只能连 `video`，`highlight` 只能连 `highlight`
- **必填输入必须连线**：未标记 `*` 的输入端口必须有连线，否则校验报错
- **可选输入**：标记 `*` 的输入端口（如 `candidates`、`highlight` 在 `output.artifact`）可以不连线
- **单输入唯一**：每个输入端口只能有一条连线（不支持多路合并）

### 6.5 内置默认工作流

系统首次启动时自动生成一套内置工作流（`is_builtin=1`），等价于原始四阶段管线：

```
input.video → preprocess.transcode → detect.candidates → analyze.highlight
                                                        ↓
                                              post.filter_segments
                                                        ↓
preprocess.transcode ─────────────────────→ edit.concat → output.artifact
                                              ↑
                                  analyze.highlight → report.technical → output.artifact
```

内置工作流不可删除或修改，但可以被其他自定义工作流「激活取代」。

### 6.6 常见问题

**Q: 激活了工作流后，为什么任务还是用旧管线执行？**
A: 检查 `workflow.mode` 配置项。如果值为 `legacy`，系统会忽略激活的工作流，使用简易模式编译的默认图。确保 `workflow.default_graph_id` 已设置且非空。

**Q: 画布上连线时报类型不匹配？**
A: 端口颜色/类型必须一致。例如 `video`（蓝色）只能连 `video`，`highlight`（绿色）只能连 `highlight`。

**Q: 任务完成了但看不到视频？**
A: 检查工作流图中 `output.artifact` 节点是否连了 `video` 输入端口（来自 `edit.concat`）。如果只连了 `highlight` 而没连 `video`，视频文件不会被投影到结果中。

**Q: 如何回到默认行为？**
A: 在画布编辑器中删除所有自定义工作流，不激活任何工作流。系统会自动回落到简易模式编译的默认图。
