## 一、功能概述

「CV 增强工作流」是随服务启动自动种子的**内置预设**（`is_builtin=1`，方案 12 · 5.2），
把 LLM 干的「找候选」「选高光」两件事拆给本地 CV 模型，LLM 只保留出报告，
即**示例 C 降本链路**：

```
input.video → preprocess.transcode → detect.tracknet → post.score_highlights ┬→ edit.concat ────┬→ output.artifact
                                    （TrackNet 球追踪）  （CLIP 零样本评分）    └→ report.technical ┘
```

| 环节 | LLM 视频理解工作流（如 LLM_Video） | CV 增强工作流 |
|------|-----------------------------------|---------------|
| 定位候选回合 | 模型直接看全片 | `detect.tracknet` 本地推理 |
| 选出高光 | `analyze.highlight` 1 次视频理解 LLM 调用 | `post.score_highlights` CLIP 本地评分 |
| 技术报告 | 视链而定 | `report.technical`（LLM 仅此 1 次，`optional` 失败不吞集锦） |
| 每任务 LLM 调用 | ≥1 次（含视频理解） | 仅报告 1 次（链中无报告节点则 0 次） |

内置属性（启动种子 `seed_builtin_presets`，按名幂等、失败仅告警不阻断）：

- 名称固定为「CV 增强工作流」，`is_builtin=1` —— **不可改名/删除/修改**，需调参请先复制副本；
- 启动时若该名称不存在则自动补种，存量库已有数据同样生效（「默认工作流」仍按全表 `count==0` 门控）；
- 激活前不影响任何现有任务：种子只是往 `workflows` 表加一行，不改激活指针。

## 二、环境准备（一次性）

```bash
cd backend
uv sync --extra cv        # 安装 torch / ultralytics / mediapipe / transformers
mkdir -p data/models      # 权重目录（.gitignore 忽略，已存在可跳过）
```

本链路只需 **2 类依赖物**（球场/球员/姿态/击球分类不在链上，无须准备）：

| 依赖物 | 来源 | 说明 |
|--------|------|------|
| TrackNet 权重 | 手动放置 `backend/data/models/tracknet.pth` | 须导出为 **TorchScript**（`torch.jit.script(model)`）或 `torch.save(完整模型)`；**裸 state_dict 不支持**（加载报错会给出导出指引） |
| CLIP 模型 | 首次运行自动从 HuggingFace 下载（需联网） | `small`=openai/clip-vit-base-patch32（默认，最快）/ `base`=patch16 / `large`=clip-vit-large-patch14（最准）；进程内缓存、后续秒加载 |

- GPU 非必需：`device=auto`（有 CUDA 用 CUDA，否则 CPU）；纯 CPU 下 TrackNet 逐帧推理较慢，可调大节点参数 `frame_stride`（2~3）降负载。
- 权重根目录固定为 `backend/data/models/`（由 `cv_runtime.MODELS_DIR` 解析，支持节点参数显式路径覆盖）。
- 缺依赖/缺权重时 `detect.tracknet` 抛 `CvUnavailable`（日志含安装/放置指引），因其 `on_failure=skip` **任务不会失败**（见「四、运行与验证」）。

## 三、激活与切换

激活是**全局指针**（`workflow.default_graph_id`），之后所有新任务走 CV 链；
`POST /api/v1/process` **没有**单任务 `workflow_id` 参数（仅 `file/md5` + `level`），
切换工作流的唯一入口就是激活。

**方式一（前端）**：App 头部「工作流」按钮 → 右侧面板 → 找到「CV 增强工作流」→ 点激活。

**方式二（API）**：

```bash
# 1. 按名称查 id（内置行 sort_order=1，排在自建工作流之后）
curl -s http://127.0.0.1:8000/api/v1/workflows | python3 -m json.tool

# 2. 激活（将 {id} 换为上一步查到的 id）
curl -X POST http://127.0.0.1:8000/api/v1/workflows/{id}/activate
```

切回原工作流：在面板中激活原条目（或再 `POST /{原id}/activate`）即可，随时可换、互不影响——
历史任务保留各自执行时的图，不受后续切换影响。

## 四、运行与验证

上传视频流程与平时完全一致（整体直传 / MD5 秒传、`level` 照旧）。按下面三层确认走上了 CV 链：

1. **启动/执行日志**出现 `workflow: start ... (graph=CV 增强工作流)`，
   且节点行为 `n3 type=detect.tracknet`、`n4 type=post.score_highlights`——
   **没有 `analyze.highlight`** 即视频理解 LLM 调用不会发生；
2. **任务详情** `GET /api/v1/db/tasks/{task_id}` 的 `workflow_nodes` 状态：

| tracknet / score 状态 | 含义 | 处置 |
|----------------------|------|------|
| `done` | 环境 OK | 正常产出集锦 + 技术报告（报告仍走 LLM，需 provider 可用） |
| `skipped`（级联下游 skipped、任务 succeeded） | 权重或依赖缺失 | 按日志 `CvUnavailable` 文案补依赖/权重后重跑 |

3. **产物**：`GET /api/v1/tasks/{task_id}/video` 可下载集锦；
   报告节点为 `optional`——LLM 失败时仅自身 `skipped`、**不级联**，
   已生成的集锦/高光投影不受影响（0.15.1 起的级联契约）。

> 级联降级语义：`detect.tracknet`（`on_failure=skip`）失败 → 自身与下游（score → edit/report →
> output.artifact）逐级标记 `skipped`、**任务状态仍为 succeeded**。
> 因此「任务成功但没有产物」= CV 环境未就绪，请查节点状态而非任务状态。

## 五、参数调参

内置预设禁止编辑：请在「工作流」面板**复制一份**（或 `GET /api/v1/workflows/{id}` 取
`graph_json` 导入新建），改完激活副本。链上四节点关键参数：

| 节点 | 参数 | 默认 | 调什么 |
|------|------|:----:|--------|
| `detect.tracknet` | `confidence` / `cluster_gap` / `top_n` / `frame_stride` | 0.5 / 4.0 / 5 / 1 | 漏检多 → 降 `confidence`；CPU 慢 → 加 `frame_stride`；回合太多 → 减 `top_n` |
| `post.score_highlights` | `clip_model` / `min_score` / `max_segments` / `highlight_phrases` | small / 0.25 / 3 / 英文高光短语 | 高光太少 → 降 `min_score` 或改描述短语；要更准 → large；段数上限 → `max_segments` |
| `edit.concat` | `target_duration` / `all_mode` | 15 / false | 集锦目标时长（5~120 秒）；全量模式忽略时长、拼接全部回合 |
| `report.technical` | `level` / `knowledge_level` | intermediate / standard | 报告分析深度（beginner/intermediate/professional）与知识库档位（basic/standard/expert） |

图结构（连线/增删节点）修改后保存时会过 R1~R10 校验，非法图返回 400。

## 六、常见问题

| 现象 | 原因 | 处置 |
|------|------|------|
| 任务成功但无任何产物，tracknet/score 为 `skipped` | 缺 `uv sync --extra cv` 或 `tracknet.pth` | 看日志 `CvUnavailable` 指引补齐后重跑 |
| TrackNet 权重加载报「不支持 state_dict」 | 导出格式不对 | 用 `torch.jit.script` 或 `torch.save(完整模型)` 重新导出 |
| CLIP 首次运行卡很久 | 正在从 HuggingFace 下载权重（需联网） | 等待一次即可，进程内有缓存 |
| CPU 跑得慢 | 逐帧推理无 GPU | `frame_stride` 调到 2~3、`clip_model` 用 small、`top_n` 收紧 |
| 激活了 CV 链但日志仍见 `analyze.highlight`/长耗时 LLM 调用 | 任务用的是别的工作流（激活指针没切 / 图里还有 analyze 节点） | 查 `GET /api/v1/workflows` 确认激活 id 与图节点 |
| 报告没出但集锦正常 | `report.technical` optional 失败（LLM 不可用） | 属预期降级，检查 provider 配置后可单独重跑任务 |
